\section{Design}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Pheromone Repulsion}

The core of our coordination system is pheromone repulsion. In a search context, high pheromone levels mean a UAV passed over a location recently. By scoring waypoints inversely to their pheromone levels, we ensure the swarm avoids redundant coverage and moves toward unexplored space. Pheromones evaporate over time to reflect that conditions might change or a victim might have been missed. The evaporation rate determines the spatial memory of the swarm and controls how quickly agents return to old areas.

\subsection{Explore and Exploit}

Pheromone repulsion is balanced by victim attraction. When a UAV detects a victim, it immediately switches from exploration to a direct approach. These two signals create a dynamic balance without any central scheduling. Repulsive pheromones push agents into unsearched space while attractive victim signals pull them toward specific targets. After a discovery, the agent stays in the area briefly to look for more victims. This local search strategy exploits the fact that victims are usually found in clusters. The swarm thus adapts its behavior through purely local signals with no global state.

\subsection{Transparent Behavior}

We prioritize behavioral transparency by using hierarchical statecharts. Every mode is a named state and every decision is an explicit transition. This design makes the controller easy to understand and ensures that each state has a single responsibility. This transparency is essential for debugging and allows researchers to reason about expected results before running simulations. It avoids the problems of opaque controllers that offer no insight into why a specific behavior occurred.

\subsection{Victim Placement}
\label{sec:design_victim}

Finally, we model victim placement using a Gaussian Mixture Model to create realistic spatial clusters. Real disasters rarely result in victims spread uniformly across an area. Using clusters allows us to test the tension between exploration and exploitation. We can configure the number and spread of these clusters to evaluate how the swarm performs across different disaster scenarios ranging from concentrated incidents to broadly dispersed sites.
